# 模块与类说明

> 本文档对应 kb-platform 工程。看完应该能清楚「哪个类该放什么代码、改需求时该动哪里」。
> `com.example.kb` 下每个包都有一份 `package-info.java`，IDE 里悬停包名即可看到同样的说明。

## 一、分层与依赖方向

```
                    ┌──────────────────────────────┐
   外部请求  ──────▶ │ controller   只做校验与转发     │
                    └──────────────┬───────────────┘
                                   ▼
                    ┌──────────────────────────────┐
                    │ service / service.impl        │  业务逻辑 · 事务边界
                    └──┬────────┬────────┬─────────┘
                       ▼        ▼        ▼
              ┌──────────┐ ┌────────┐ ┌────────────┐
              │ mapper   │ │ vector │ │ retrieval  │
              │ MySQL    │ │pgvector│ │ 召回 + 融合 │
              └──────────┘ └────────┘ └─────┬──────┘
                                           ▼
                                     ┌──────────┐
                                     │   ai     │  大模型 / Embedding
                                     └──────────┘

  横切支撑：common（返回体/异常/工具） · config（配置与 Bean） · security（鉴权过滤器） · init（启动初始化）
```

依赖方向是单向的：**controller → service → (mapper | vector | retrieval | ai) → 无**。
`common` 和 `config` 谁都可以依赖，但它们不依赖上面任何一层。

## 二、模块清单

| 包 | 作用 | 依赖谁 | 典型改动场景 |
|---|---|---|---|
| `common.result` | 统一返回体、错误码、分页体 | 无 | 新增错误码 |
| `common.exception` | 业务异常 + 全局兜底 | `common.result` | 新增异常处理分支 |
| `common.util` | JWT、当前用户、文本切分 | 无 | 调切分算法、加解密工具 |
| `config` | 所有 Bean 与配置绑定 | 全部基础组件 | 加数据源、改线程池参数 |
| `security` | JWT 解析过滤器 | `common.util` | 改鉴权白名单、加权限校验 |
| `domain.entity` | 数据库实体 | 无 | 加字段、加表 |
| `domain.dto` | 入参 + 校验规则 | 无 | 接口新增参数 |
| `domain.vo` | 出参 | `domain.entity` | 前端要新字段 |
| `mapper` | 单表 CRUD | `domain.entity` | 加复杂查询 |
| `vector` | pgvector 读写 | `domain` 无关 | 换向量库、调检索 SQL |
| `retrieval` | 关键词抽取 + RRF 融合 | `vector`、`ai` | 调检索策略（本项目最常改的地方） |
| `ai` | 大模型抽象与实现 | 无 | 换模型、换 Spring AI |
| `service` / `service.impl` | 业务编排 | 上面全部 | 加业务规则 |
| `controller` | HTTP 接口 | `service` | 加接口 |
| `init` | 启动初始化 | `mapper` | 加种子数据 |

## 三、逐类说明

### 3.1 common —— 横切能力

| 类 | 作用 | 关键点 |
|---|---|---|
| `ResultCode` | 错误码枚举 | 0 成功；400 参数；401 未登录；403 无权限；404 不存在；500 业务失败；999 系统异常。前端只认 code |
| `R<T>` | 统一返回体 | 提供 `ok()` / `ok(data)` / `fail(code)` / `fail(code, msg)` 四个静态工厂 |
| `PageResult<T>` | 统一分页体 | 字段 `list / total / page / size`，避免每处各写一套 |
| `BizException` | 业务异常 | 携带 `ResultCode`，`of(msg)` 用于只关心提示语的场景 |
| `GlobalExceptionHandler` | 全局兜底 | 业务异常打 warn 返回原始码；参数校验异常返回字段级提示；未知异常打 error 但对外只回「系统繁忙」 |
| `JwtUtil` | 签发与解析 token | 用 jjwt 0.12 API；密钥来自 `kb.jwt.secret`，长度必须够 256 bit |
| `UserContext` | 当前登录用户 | ThreadLocal 存 userId / username；**必须在 finally 里 clear**，否则线程池复用会串号 |
| `TextSplitter` | 递归字符切分 | 段落 → 句子 → 硬长度三级；输出时为相邻段加 overlap 重叠，防止答案落在切口上 |

### 3.2 config —— 配置与 Bean

| 类 | 作用 | 关键点 |
|---|---|---|
| `KbProperties` | `kb.*` 全部自定义配置 | 内含 `Jwt / Ai / Retrieval / Chunk / Storage` 五个静态内部类；`Ai.mock()` 判断是否降级 |
| `DataSourceConfig` | 双数据源 | MySQL 标 `@Primary` 给 MyBatis-Plus 用；PostgreSQL 单独建 `vectorDataSource` + `vectorJdbcTemplate` |
| `MybatisPlusConfig` | 分页插件 | **不加这个 Page 查询会返回全表** |
| `RedisConfig` | 序列化 | key 用 String，value 用 JSON，方便在 redis-cli 里直接看 |
| `AsyncConfig` | `aiExecutor` 线程池 | 核心 4 / 最大 8 / 队列 200 / CallerRunsPolicy；解析与模型调用都跑在这里，和 Web 线程隔离 |
| `OpenApiConfig` | 接口文档元信息 | 访问 `/doc.html` |
| `SecurityConfig` | 过滤器链 | 无状态、关 CSRF、放行登录与静态资源；未登录也返回统一返回体而不是 403 页面 |

### 3.3 security

| 类 | 作用 | 关键点 |
|---|---|---|
| `JwtAuthenticationFilter` | 解析 `Authorization: Bearer` | 解析成功写入 `UserContext` + `SecurityContext`；失败只清空上下文不抛异常；`finally` 里清理 ThreadLocal |

### 3.4 domain —— 三个子包的边界

| 子包 | 放什么 | 不放什么 |
|---|---|---|
| `entity` | 与表一一对应的字段 | 业务方法、DTO 注解 |
| `dto` | 接口入参 + 校验注解 | 持久化注解 |
| `vo` | 接口出参 + 静态 `from(entity)` 转换 | 敏感字段（如密码） |

实体：`User`（含 `@JsonIgnore` 的密码）、`KnowledgeBase`（含 per-KB 的切分参数）、
`KbDocument`（含状态机常量）、`Conversation`、`Message`（只追加，无逻辑删除）。

### 3.5 mapper / vector —— 两条数据通路

| 类 | 作用 | 关键点 |
|---|---|---|
| `XxxMapper` × 5 | 单表 CRUD | 继承 `BaseMapper`，零 SQL；逻辑删除由 `deleted` 字段自动生效 |
| `ChunkVector` | 向量库的一条切片 | `score` 只在检索结果里有值，融合后放的是 RRF 分数 |
| `VectorRepository` | pgvector 读写 | `saveAll` 写入；`search` 向量召回；`searchByKeyword` 关键词召回；所有 SQL 都带 `kb_id` |

### 3.6 retrieval —— 检索策略（本项目最值得讲的一层）

| 类 | 作用 | 关键点 |
|---|---|---|
| `KeywordExtractor` | 从问题抽关键词 | 中文按 2-gram 切，拉丁词整词保留；上限 8 个，避免拼出几十个 OR 条件 |
| `RrfFuser` | RRF 融合 | `score = Σ 1/(k+rank)`，只用排名不用分数，所以不必做量纲归一化；纯静态类，可直接单测 |
| `HybridRetriever` | 检索入口 | 先向量召回 Top20；`mode=hybrid` 时再关键词召回 Top20，融合取 Top5；关键词为空时自动退化为纯向量 |

### 3.7 ai

| 类 | 作用 | 关键点 |
|---|---|---|
| `AiClient` | 大模型抽象 | `dimension / embed / embedBatch / chatStream / chat`；业务层只依赖它 |
| `OpenAiCompatibleAiClient` | 默认实现 | 分批调用 Embedding（默认 16 条）并指数退避重试；chat 走 SSE 解析逐段回调；未配 Key 时降级为本地哈希向量 + 占位回答 |

### 3.8 service —— 四组业务能力

| 接口 | 实现 | 职责 |
|---|---|---|
| `AuthService` | `AuthServiceImpl` | 注册、登录、取当前用户；用户不存在与密码错误返回同一句提示，避免撞库枚举 |
| `KnowledgeBaseService` | `KnowledgeBaseServiceImpl` | 知识库 CRUD；`getOwned` 做归属校验，`getById` 不做校验供异步线程用 |
| `DocumentService` | `DocumentServiceImpl` | 上传、异步解析、重新解析、分页、删除；扫描件识别 |
| `ChatService` | `ChatServiceImpl` | 会话与消息、RAG 问答、历史上下文、引用来源组装 |

### 3.9 controller / init

| 类 | 作用 |
|---|---|
| `AuthController` | `/api/auth/**`：注册、登录、当前用户 |
| `KbController` | `/api/kb/**`：知识库增删改查分页 |
| `DocumentController` | `/api/doc/**`：上传、列表、详情、重新解析、删除 |
| `ChatController` | `/api/chat/**`：会话、消息、普通问答、SSE 流式问答 |
| `DataInitializer` | 首次启动建 `admin / 123456`，密码运行时 BCrypt 加密 |

## 四、命名与约定

- Controller 不写业务逻辑，Service 不写 SQL，Mapper 不写判断。
- entity 绝不直接返回前端，一律转 VO。
- 事务注解只加在 Service 的 public 方法上，且不要在同类内部互调。
- 异步任务一律 `executor.execute(...)` 显式提交，不用 `@Async`（同类内部调用不走代理，注解会静默失效）。
- 所有外部输入先落 DTO 并用校验注解，不在 Controller 里写 `if (x == null)`。
